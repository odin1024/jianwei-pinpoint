## 二、关键发现

### 1. 它不扫漏洞——这是和我们的根本区别

README 开篇一句话定位：

> **本工具不扫漏洞、不修代码。** 它把 212 条 PHP/Linux 加固建议变成可审阅、可执行、可回滚的配置变更。

也就是说，**它需要你手动告诉它目标 INI 的绝对路径**：

```sh
./configtools-linux export production 8.3 /etc/php/8.3/fpm/php.ini /tmp/policy.json
```

它没有端口扫描、没有协议识别、没有设备分类、没有 PHP 暴露面判定。
**发现能力为零，执行能力很强。**

### 2. 执行模型：两阶段票据 + 一次性授权（最值得借鉴）

```
export  → 生成策略 JSON（不碰系统）
preview → 读取当前存储态，生成加密快照 + 票据，仍然不写目标
apply   → 消费票据写入，需 --confirm-apply，票据只能成功用一次
```

配套约定：
- `apply` 只认 `--confirm-apply`，`rollback` 只认 `--confirm-rollback`，**混用直接报错**；
- 改动方案后旧票据**自动作废**，必须重新 preview；
- 「计划文件是给人看的摘要，真正执行的是本机加密票据」——
  **不要把 A 机的计划摘要当 B 机的授权**。

### 3. 拒绝清单（非常硬，我们目前只有一部分）

从 README 第 11 节的报错表可反推出它主动拒绝的场景：

| 场景 | 它的处理 |
|---|---|
| 文件不属于当前账号 | 拒绝，**不做隐式提权** |
| 组/其他用户可写 | 拒绝，要求先 `chmod go-w` |
| 软链 / 多硬链接 | 拒绝，只接受单链接常规文件 |
| 路径上有他人可写目录 | 拒绝（防 TOCTOU） |
| 同一指令出现多次 | 拒绝，**不猜哪条生效** |
| 存在 `\` 续行 | 拒绝，要求人工整理成单行 |
| 目标里没有该指令 | 拒绝自动插入，转人工 |
| 指定的 `[section]` 不存在 | 拒绝 |
| 策略库版本不匹配 | 拒绝，要求重新 export |
| 预览后目标被外部改动 | `Target changed since preparation` |

写入用 `renameat` 原子替换 + `flock` + `fsync`；快照保留字节、权限、属主、属组、扩展属性。

### 4. 加密与合规

- `.ctd` 文件头 `43 54 44 31 01 01 00`（即 `CTD1`），**熵 8.00 bits/byte** → 全量加密；
- 算法为 **SM4-CTR + HMAC-SM3**（国密），实现在二进制内，不依赖 OpenSSL；
- 知识与动作数据在构建时加密嵌入，加载时校验完整性；
- README 自己承认：「内置密钥可被逆向提取」——**诚实**。

### 5. 本机 Web 界面

`--web [PORT]`，仅监听 `127.0.0.1`：

- 启动输出 `http://127.0.0.1:8134/#<64位令牌>`，令牌放 URL **片段**（不进 Referer/日志）；
- POST 校验 Host、Origin、`X-CT-Session`、`Sec-Fetch-Site`；
- 页面启用 CSP nonce、`X-Frame-Options: DENY`；
- 无公网监听选项，无任意命令接口。

静态分析印证：二进制里确有 `Content-Security-Policy`、`X-CT-Session`、`X-Frame-Options`、`nonce`、`Origin` 等字符串。

### 6. 覆盖面与真实执行范围

| 项 | 数量 |
|---|---|
| 知识规则 | **212 条**，13 类（Linux），中英文对照 |
| 其中可自动执行 | **194 项**（18 项标注为人工流程） |
| **方案真正会执行的** | basic **3 项** / production **6 项** / strict **7 项** |
| 非 PHP 扩展 | SELinux 原生策略、systemd drop-in、nginx/apache include 片段、K8s Pod/NetworkPolicy JSON |

它自己特别提醒：**「不要把 212 条知识当作 212 项可执行」**。

### 7. 最值得学习的一点：如实标注未验证状态

README 第 12 节原文：

> 本轮构建已完成 C++ 单元测试、Python 契约测试、夹具端到端检查与双语只读烟测；
> **未在真实业务站点做原生配置语法、加载链与服务激活验证**
> （`service_activation_tested: false`）。
> 所有报告与烟测均带 `runtime_verified: false`——存储态正确不等于运行时生效。

这种"把没做到的部分写在最显眼处"的做法，比任何功能都更能建立信任。

## 四、结论与建议

### 定位判断

**不是替代关系，是上下游关系。**

- 它回答「**知道要改什么之后，怎么安全地改**」；
- 我们回答「**这台机器有没有问题、问题有多严重、改完有没有效**」。

它没有发现能力，我们的发现能力是它完全缺失的一环；反过来，它的执行安全模型比我们成熟一个量级。

### 建议补的 5 件事（按性价比排序）

| # | 事项 | 理由 |
|---|---|---|
| 1 | **回执升级为一次性授权票据** | 我们已有 HMAC token 接口（10 分钟有效），但执行侧不强制消费；应改成 plan-hash + 一次性 token，apply 时校验并作废 |
| 2 | **rollback 加冲突检查** | 现在直接覆盖备份，若执行后有人合法改过文件，回滚会抹掉别人的改动 |
| 3 | **扩充拒绝清单** | 软链/多硬链/组可写/重复指令/续行，这 5 条我们现在只覆盖了部分（容器/权限/sha/配置管理） |
| 4 | **规则库从 4 条扩到 20–30 条** | 每条带「副作用、验证方法、恢复说明」，这才是"知识库"而非"配置项列表" |
| 5 | **报告标注 `runtime_verified`** | 我们已有"存储态 vs 运行时"的区分（FPM 文件校验 vs CLI 运行时校验），应在报告里显式标出 |

### 不必跟的

- **国密加密知识库**：他们加密是为了保护"规则资产"，但自己承认可被逆向。我们开源/私有化交付的定位不同，加密收益低。
- **SELinux/systemd/K8s 全覆盖**：摊子铺太大，212 条里 205 条不可自动执行，边际价值有限。

### 一句话总结

> 他们的强项是**「变更的工程纪律」**，我们的强项是**「发现的判断纪律」**。
> 前者可以直接抄，后者他们抄不了——因为没有检测就没有判断。
