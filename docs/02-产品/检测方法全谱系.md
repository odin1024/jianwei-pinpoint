# php2shell 检测方法全谱系

> 回答一个问题：这个漏洞到底有几种查法？哪种能下结论、哪种只能给线索？
> 以及：**为什么必须有本地 Agent 组件，不能只靠远程扫。**

---

## 零、一句话结论

**远程只能"怀疑"，本地才能"证明"。**

| | 远程探测（无 Agent） | 本地取证（Agent / 本机） |
|---|---|---|
| 能回答 | 版本号像不像、SAPI 是什么、配置是否可疑、暴露面多大 | **实际安装的二进制、包 changelog、生效配置、进程、日志、落地文件** |
| 不能回答 | ① 发行版是否**已回移补丁**（版本号低但已修，会误报）<br>② 版本号是否被**改写**（自编译，会漏报）<br>③ **有没有已经被打进去** | — |
| 结论形态 | `疑似受影响 / 疑似已修复 / 无法判定` | `确认受影响 / 确认已修复 / 疑似失陷` |

这不是能力取舍，是**证据物理位置**决定的：补丁痕迹在文件系统里，攻击痕迹在日志和进程里，远程拿不到。

## 一、八类检测方法（按证据强度排序）

| # | 方法 | 原理 | 需要什么 | 单独能定性吗 | 本工具 |
|---|---|---|---|---|---|
| **M1** | 版本指纹 | 读 `X-Powered-By` / `Server` / `phpinfo` / 错误页，比对修复基线 | 只要能访问 HTTP | ❌ 只能作线索 | ✅ 远程 `discover` / `assets` |
| **M2** | 主动行为差分 | 发一个**无害**的放大请求，对比控制请求的响应差异（空 500、OOM 文案、worker 重启） | 网络可达 + 授权 | ❌ 辅助证据 | ✅ `p2s probe`（gentle/standard） |
| **M3** | 受控 OOM 探针 | 让 worker 达到 `memory_limit`，看补丁前后行为差异 | 授权 + 可回滚 + 低峰 | ❌ 辅助，可能影响业务 | ⚠️ 本版本未内置（D5 设计保留） |
| **M4** | 包元数据核验 | `rpm -q --changelog` / `zcat changelog.Debian.gz` / `apk info` 里找 `CVE-2026-10961[89]` | **本机只读权限** | ✅ **回移补丁的唯一解** | ✅ `hostcheck` + Agent |
| **M5** | 二进制构建指纹 | ELF BuildID / 构建时间 / 导出符号 / 补丁前后差异字节序列 | 本机文件读权限 | ✅ 强证据 | ⚠️ 部分（版本+构建日期已做，标记字节未做） |
| **M6** | 源码/构建日期核验 | 构建日期早于补丁日 → 必未修复；源码里是否仍直接 `longjmp` | 本机 + 源码 | ✅ 强证据 | ✅ 构建日期已进 D4 逻辑 |
| **M7** | 生效配置核验 | `php -i` / FPM pool / Apache 配置里的**实际生效值**，以及 worker 是否重启 | 本机只读权限 | ✅ 回答"缓解是否真生效" | ✅ `hostcheck.check_settings` |
| **M8** | 失陷排查 | 日志（启动期 OOM 聚集、大 POST 关联、异常 PHPSESSID）、落地 webshell、异常进程、外连 C2 | 本机日志/文件/进程 | ✅ 回答"有没有被打过" | ✅ `logscan` + `hostcheck.scan_artifacts` |

另有两类**不是查漏洞、但决定处置优先级**的方法：

| # | 方法 | 作用 | 本工具 |
|---|---|---|---|
| **M9** | 镜像/固件离线解析 | 容器 layer、固件 squashfs 里找 PHP 运行时（设备厂商场景） | ❌ 未实现（规划中） |
| **M10** | 资产暴露面测绘 | 先回答"哪些设备跑 PHP"，否则前面的方法都无从下手 | ✅ L0–L4 五层收敛 |

## 二、各方法的可靠性对照

| 方法 | 单独可信度 | 典型误判 | 我们的处理 |
|---|---|---|---|
| M1 版本指纹 | 中 | 发行版回移补丁 → 误报；自编译改版本串 → 漏报；CDN 改写头 → 误报 | 只作线索，结论里显式标注"未经物料核验" |
| M2 行为差分 | 中低 | 低 `memory_limit`、前置代理、worker 模型都会改变表现 | 只作辅助，不单独定性；差异 + 版本未修复才升级结论 |
| M3 OOM 探针 | 中 | 可能把 worker 打崩，本身有 DoS 风险 | 双开关 + 前置/后置健康检查 + 单次不重试 |
| M4 changelog | **高** | changelog 被裁剪 / 容器镜像里没有包管理信息 | 命中即"已修复"；未命中时降级到 M5/M6 |
| M5 二进制 | **高** | 需要样本；STRIP 过的二进制特征弱 | 与 M4 互证 |
| M6 构建日期 | 高 | 只对"早于补丁日"有效，之后无法判断 | 早于补丁日 → 必未修复；晚于 → 仍需 M4/M5 |
| M7 配置 | 高（但只答"缓解"） | 改了 ini 没重启 worker → 假安全 | 采集 worker 启动时间与配置修改时间比对 |
| M8 失陷 | 中高 | 成功利用可能既不崩溃也不报错 → 日志干净≠没被打过 | 结论写"未发现证据"，不写"未被打过" |

**判定优先级（证据链）**：`本地 changelog/binary` > `本地构建日期/配置` > `远程版本` > `远程行为`。
冲突时不取多数票，按**保守方向**（判受影响）并标记人工复核。

## 三、本工具怎么落地（三种形态）

```
① 远程（零权限）     p2s discover / assets / probe      →  M1 + M2 + M10
② 本机（本机运行）    p2s host                          →  M4 + M6 + M7 + M8
③ Agent（目标主机）   p2s agent --console ... --token …  →  M4 + M6 + M7 + M8，上报平台
④ 下载即用（推荐）    控制台「主机侧检测」页 → 下载脚本    →  同 ③，但目标主机不需要装 Python
```

### ④ 下载即用脚本（客户现场零安装）

在控制台「主机侧检测」页点两个按钮即可拿到脚本，**平台地址与上报令牌在下载时已注入**：

| 脚本 | 覆盖系统 | 依赖 | 运行方式 |
|---|---|---|---|
| `p2s-agent.sh` | CentOS/RHEL 6+、Ubuntu 14.04+、Debian 8+、Alpine 3+、麒麟/统信 | `sh` + `curl` 或 `wget`（系统自带） | `sh p2s-agent.sh` |
| `p2s-agent.ps1` | Windows 7 / Server 2008R2 及以上（PowerShell 5.1 自带） | 无 | `powershell -ExecutionPolicy Bypass -File p2s-agent.ps1` |

工程细节（都是踩过的坑）：

- **Windows 脚本必须带 UTF-8 BOM**：PS 5.1 在无 BOM 时按系统 ANSI（中文 Windows 是 GBK）解析 `.ps1`，中文注释会乱码甚至吞掉换行导致语法错误；
- **PS 5.1 的 Body 必须显式转 UTF-8 字节**，否则中文证据会被按 ISO-8859-1 编码成问号；
- **脚本只报事实，判定在服务端算**：版本 → 修复状态、changelog 命中 → 已回移补丁、ini 实际值 → 是否达标，全部由控制台统一计算，脚本改版不影响结论口径；
- 支持 `--dry-run` / `-DryRun` 先看 JSON 再上报，`--out` 可落盘后人工上传。

### Agent 路径（这轮打通的部分）

```
目标主机                                    控制台
┌──────────────────────────┐              ┌─────────────────────────────┐
│ p2s agent                │  POST        │ /api/agent/report           │
│  · 枚举 PHP 安装点        │  X-P2S-Token │  · 校验令牌（防投毒）        │
│  · 读生效配置             │ ───────────► │  · 折算成 exposure 结论      │
│  · 扫落地痕迹/进程/连接    │  主机报告     │  · **写入资产台账**（R-05）   │
│  · 失败重试 + 抖动        │              │  · 本地结论覆盖远程推断       │
└──────────────────────────┘              └─────────────────────────────┘
```

关键语义：

- 本地结论写入台账时带 `evidence_level="host"`、`confidence=0.95`，**覆盖**远程推断出的 `暴露/已修复`；
- 主机报告完整留存（安装点路径、版本、SAPI、生效配置、痕迹、进程、连接），可在资产详情里追溯；
- 同一主机重复上报会走**变更检测**，配置漂移/版本变化会被记为 `changed`；
- 没装 PHP 的主机会被标成 `not_php`，不再占用"待确认"名单。

### 为什么必须走 Agent，而不是让运维手工跑脚本

| 场景 | 手工脚本 | Agent |
|---|---|---|
| 100 台机器 | 逐台登录、逐台收结果 | 一次分发、自动上报、失败重试 |
| 容器/编排环境 | 无法逐台登录 | sidecar 常驻 |
| 无法出网 | 结果靠人拷 | 允许单向出站即可 |
| 证据留存 | 散落在聊天记录 | 台账 + 报告 + 变更历史 |

## 四、当前实现的边界（不粉饰）

| 项 | 状态 |
|---|---|
| M4 changelog 核验（rpm/deb/apk） | ✅ 本机与 Agent 都做 |
| M6 构建日期核验 | ✅ 已进判定逻辑 |
| M7 生效配置 + worker 重启判断 | ✅ 采集了启动时间，判定规则待细化 |
| M8 日志/痕迹/进程/连接 | ✅ 日志规则 13 条 + 痕迹扫描 + IOC |
| M5 二进制标记字节 | ⚠️ 需要补丁前后样本才能做，暂以 BuildID/构建日期替代 |
| M3 受控 OOM 探针 | ⚠️ 设计保留、默认关闭（风险高，交付版不建议默认开启） |
| M9 镜像/固件离线 | ❌ 未实现 |
| Agent 自动升级 / mTLS | ❌ 未实现（当前是共享令牌 + 明文 HTTP，内网可用） |
