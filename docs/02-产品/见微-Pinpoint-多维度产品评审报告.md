## 一、本轮已修复的关键问题

### 1.1 真实功能性 Bug（3 个）

#### BUG-01　favicon 指纹从未生效　【严重度：中】

```python
# 修复前：client 在 with 块结束时已关闭，这里再用必然抛异常，
# 而异常被 except: pass 静默吞掉 —— favicon 哈希永远是 None
with httpx.Client(...) as client:
    ...
if favicon:
    fr = client.get(f"{base}/favicon.ico")   # ← client 已关闭
```

**影响**：favicon 指纹是识别同款管理界面的强信号，此前 100% 失效，且无任何报错提示。
**修复**：另开一个短生命周期连接。已实测可取到哈希。

#### BUG-02　CLI 与 Web 用两套识别引擎　【严重度：高】

```python
# cli.py 的 assets 命令走的是旧的 probe_mod.fingerprint：
#   无存活判定  → 离线主机照样入库
#   无设备分类  → 只能看到版本，看不到"这是什么设备"
# Web 控制台的 discover 走的是新引擎（有存活判定 + 设备分类）
```

**影响**：**同一份资产清单，CLI 和 Web 给出不同结论**。客户用 CLI 跑一遍会得到 254 条「未识别设备」，用 Web 跑得到 17 条精准结果 —— 会被直接质疑工具不可信。
**修复**：`core/fingerprint.py` 改为 `core/discovery.py` 的薄封装，双引擎合一。已验证 CLI 与 Web 输出完全一致。

#### BUG-03　检测结果与报告字段不匹配　【严重度：中】

设备发现产出的资产没有 `host` 字段只有 `url`，而资产台账、报告、CSV 导出全部按 `host` 读写 —— 结果是**发现页有数据、台账页空白**。
**修复**：统一为 `host`，报告层兼容 `host or url`。

## 三、产品价值再审视

### 3.1 真正的差异化是什么

| 能力 | 市面常见工具 | 见微 Pinpoint |
|---|---|---|
| 存活判定 | 只看 TCP 握手 | **必须拿到有效协议响应**（NAT/tarpit 环境零假阳性） |
| 设备识别 | 端口画像 | **133 条标签签名**（标题/证书/登录路径/Set-Cookie/banner/favicon/OUI） |
| 结论形态 | 是/否 | **置信度 + 候选类型 + 完整证据链** |
| 安全边界 | 视工具而定 | **绝不发利用载荷**（代码级强制 + CI 门禁） |
| 可解释性 | 弱 | 每条结论可复核到原始 banner / 证书 / 标题 |

这五条应当成为**对外销售话术的主线**，而不是埋在文档里。

### 3.2 一句话价值主张（建议用于交付材料首页）

> 在攻击者找到你之前，先找到那**一个**跑着旧版 PHP 的机器。

### 3.3 目标客群建议收敛

当前功能横跨"资产测绘"和"合规评估"两条线。对**中小企业**而言，"PHP 暴露面评估"是伪需求（他们往往连 PHP 有几个都不知道），真正的需求是"帮我看看内网有什么、哪些有风险"。

建议：
- **主产品定位**：内网资产测绘 + 风险发现（覆盖 php2shell 这类高危暴露面）
- **php2shell 作为内置的专项检测模块**（而非产品名）—— 这也解释了小工具与平台级产品的差异
- 面向**乙方交付**的场景（帮客户摸底、出报告）价值最高，**面向甲方日常运维**需要认证 + 调度 + 变更告警才成立

```
中性层   --bg #f2f3f5   --surface #fff   --surface-2 #f7f8fa   --surface-3 #edeff2

| 维度 | 评价 |
|---|---|

## 六、结论与建议的下一步

### 6.1 当前状态可交付吗？

**可以交付给乙方做项目实施**，前提是：
- 部署在客户内网、监听 127.0.0.1 或加反向代理
- 客户书面确认扫描范围
- 报告交付前人工复核低置信度结论

**不建议直接作为甲方长期运维平台**，因为：
- 无认证（R-01）
- 无调度（R-11）与变更告警（R-07）
- 资产存储不适合规模（R-12）

### 6.2 建议的迭代顺序

```
