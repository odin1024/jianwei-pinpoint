## 六、v0.5.2：设备识别重写（严重误报）

**现象**：一批捷普安全设备被识别成「JumpServer 堡垒机」，并冒出「深信服 / 海康威视」品牌。

**根因**：不是签名少，是**证据分级缺失** —— 用服务级证据（`Server: Jump_server`）去推
厂商级结论（这是谁家的产品）。具体四处错误：

1. 把捷普自研 Web 服务的 `Server: Jump_server / Jumper / jump` 映射成别家的 JumpServer；
2. 把捷普内部 PKI（证书 `O=jump`、`ST=shan'xi`、`jump.net.cn` / `yanfa.net.cn`）映射成 JumpServer；
3. 标题`捷普WEB应用防火墙`只提取了"应用防火墙"，**把厂商信息丢了**；
4. 把 MAC OUI 查到的「深信服 Sangfor」直接写进设备厂商。

**修复**：

| 改动 | 说明 |
|---|---|
| 证据分级 T1/T2/T3 | T1（标题/证书/登录路径/认证域）才能定厂商与产品；T2（Server/banner/Cookie/正文）只能定技术栈；T3（端口/OUI）只能兜底且必须标注 |
| T2 折算系数 0.7 + 置信度封顶 0.72 | 服务级证据永远压不过同权重的产品级证据 |
| 新增捷普产品族签名 | WAF / 防火墙 / 信息审计 / 准入控制 / 演示平台，全部带厂商与产品名 |
| JumpServer 改用真指纹 | 只认 Fit2Cloud 证书与页面里的 jumpserver 品牌词 |
| OUI 不再进厂商字段 | 只作"网卡厂商"，详情里注明不代表设备品牌 |
| 端口推断只用有效端口 | 没有有效响应就不猜类型（此前把 tarpit 的 25/110/143 推成"邮件网关"） |
| 跨主机 favicon 聚类 | 同指纹且本批次只有唯一已知型号时才补型号，置信度封顶 0.6 |

**验证**（同批 11 台真机复扫）：捷普 10 台全部归到厂商"捷普"，
1 台无任何产品级证据诚实显示"未识别"，JumpServer / 深信服 / 海康威视全部消失。
详见 [`设备识别逻辑说明.md`](./设备识别逻辑说明.md)。
