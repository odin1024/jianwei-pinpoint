# 文档地图

本仓库有两处文档目录，**分工不同、互不重复**。这份文件定义"查什么看哪里、以哪份为准"。

## 一、为什么会有两处

| 目录 | 定位 | 读者 | 变更节奏 |
|---|---|---|---|
| `docs/`（本目录） | **决策与背景**：立项、产品设计、漏洞情报、部署方案 | 产品/管理/售前 | 阶段性，归档为主 |
| `app/docs/` | **技术手册**：架构、检测原理、平台适配、客户部署 | 开发/交付/运维 | 随代码版本走 |

技术手册放在 `app/` 里，是因为它要**跟代码一起打包交付**（`tools/package_release.py` 会把它们打进发行包）；
项目文档放在根目录，因为它不属于代码产物。

## 二、按主题查哪里（权威定义）

| 我想了解 | 看这份 | 说明 |
|---|---|---|
| 这个漏洞是怎么回事 | `docs/03-情报/01-PHP-php2shell漏洞全面情报报告.md` | 情报汇总 |
| 官方公告原文 | `docs/03-情报/02-*`、`03-*` | CVE 原文（不可修改） |
| 产品需求与设计 | `docs/01-立项/02-产品需求规格说明书(PRD).md` | 需求基线 |
| **系统架构** | **`app/docs/ARCHITECTURE.md`** | 随代码更新，**以这份为准** |
| **检测方法与规则** | **`app/docs/DETECTION.md`** | 随代码更新，**以这份为准** |
| **客户部署步骤** | **`app/docs/DEPLOY-CUSTOMER.md`** | 随代码更新，**以这份为准** |
| 支持的平台 | `app/docs/PLATFORMS.md` | 随代码更新 |
| 加固做了什么 | `docs/02-产品/配置加固设计.md` | 设计意图（实现见 `app/src/p2s/core/hardening.py`）|
| 设备识别逻辑 | `docs/02-产品/设备识别逻辑说明.md` | 指纹与判定规则 |
| 反向代理与 TLS | `docs/04-部署/反向代理与TLS.md` | 部署补充 |
| **改了什么、为什么改** | **`CHANGELOG.md`（项目根）** | **唯一权威的变更记录** |
| 当前版本号 | `app/src/p2s/__init__.py` | 代码里的单一来源 |
| 开发规范 | `CONTRIBUTING.md`（项目根） | 每条规范都对应一次真实事故 |

**冲突处理原则**：技术描述以 `app/docs/` 为准（它随代码走）；变更历史以 `CHANGELOG.md` 为准。

## 四、目录速览

## 五、写文档的三条约定

1. **不写会过期的数字**——要么不写，要么注明验证日期（如"2026-11-25 实测"）；
2. **历史快照不改**——发现问题就在文首加一行指向当前文档，保留原文；
3. **新增能力必须同时更新 `CHANGELOG.md`**，否则等于没做（这是本项目踩过最多次的坑）。
