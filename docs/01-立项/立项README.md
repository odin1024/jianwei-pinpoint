## 二、三分钟看懂这个项目

### 问题

2026-10-21，PHP 爆出两个内核级 RCE 漏洞（CVSS 9.2），影响近十年所有版本、全球约 70% 网站、百万级以上暴露主机。攻击量在 48 小时内从数千次升至数百万次，多国政府网站紧急关停。

**关键点：漏洞在 PHP 解释器内核，不在应用代码。** 网站代码写得再规范也拦不住；WAF、安全插件、`disable_functions`、代码审计全部无效。唯一有效手段是升级 PHP 运行时。

### 现有检测手段为什么不够

| 现有方案 | 做法 | 致命短板 |
|---|---|---|
| OpenAI 开源 `php2shell-checker` | 读 HTTP 头 / `php -v`，做版本区间比对 | ① 头部隐藏即 `UNKNOWN`；② 无法识别发行版**回移补丁**（版本号低但已修）→ 大量误报；③ 无法识别**版本号造假**（自编译）→ 漏报；④ 不查配置、不查失陷 |
| 通用漏扫（Tenable/Qualys 等） | 通用版本指纹插件 | 对 backport 误报高，对 109619 这类配置依赖型判定粗 |
| 手工脚本 | `php -v` + `grep` changelog | 无法规模化、结论不可复现、无证据链 |

### 我们的解法

**不做“版本号比对”，做“补丁级核验”。**

用五类证据交叉验证，回答一个可证伪的问题：**这台机器上的 PHP 运行时，到底有没有包含这次的安全修复？**

```
L1 被动指纹（HTTP）        ── 线索，权重低
L2 主动安全探测（非破坏性）── 补全盲区
L3 主机事实（SAPI/真实二进制/INI/进程/重启时间）
L4 补丁标记核验（包 changelog / 二进制特征 / 源码提交）── 决定性证据
L5 受控行为验证（可选，需授权）── 辅助证据
   ＋ D6 失陷排查（回答“修之前有没有被打进去”）
```

输出不是“有/无漏洞”，而是五级结论 + 0–100 风险分 + 完整证据链：
`VULNERABLE` / `LIKELY_VULNERABLE` / `PATCHED` / `NOT_APPLICABLE` / `UNKNOWN`

> **`UNKNOWN` 是一等公民。** 证据不足时明确说“不确定”，而不是默认判“安全”。这是产品能否被长期信任的分水岭。

### 三条必须守住的红线

1. **不内置 RCE 利用代码**。探针只发随机填充触发一次 OOM，不含任何用于内存布局的数据结构 —— “检测”与“攻击”的技术分界线画在代码里。
2. **默认不触发 OOM**。高危探针默认关闭，需授权 + 健康检查 + 单次 + 熔断。
3. **不推荐 `RLIMIT_AS`/`RLIMIT_DATA` 做缓解**。官方明确警告这会重新触发脆弱路径，是“看似加固、实则扩大攻击面”的陷阱。

## 三、开发启动清单（本周可做的 5 件事）

- [ ] **搭靶场**：`php:8.4.26-apache`（未修）、`php:8.4.27-apache`（已修）、`php:8.3.35-fpm`（未修）、Ubuntu 回移补丁版 —— 这四个样本就能验证核心判定逻辑
- [ ] **验证回移补丁场景**：在 Ubuntu/麒麟上执行 `zcat /usr/share/doc/php*-common/changelog.Debian.gz | grep CVE-2026-10961`，确认能否稳定识别
- [ ] **验证版本造假场景**：自编译一个版本字符串为 8.4.27 但未合补丁的 PHP，测试判定是否会被骗
- [ ] **对齐公司现有平台**：确认与 seccheck（FastAPI/8848/SQLite WAL、7 角色 RBAC）的资产模型与鉴权是否复用
- [ ] **决策首发形态**：CLI 优先（2 周可用）还是 Web 优先（6 周可用）—— 建议 CLI 先行，内部先用起来

## 四、关键结论备忘

| 项 | 结论 |
|---|---|
| 修复版本 | PHP 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 |
| 无修复 | 8.1 及更早（含 7.x/5.x，可追溯至 5.4），只能迁移 |
| 最高风险配置 | Apache + mod_php（请求启动阶段即可触发，无需应用代码） |
| 在野利用起点 | **2026-10-17**（早于披露 4 天）→ 日志回溯务必从这天开始 |
| 最有效单一检测指标 | 异常 `PHPSESSID` 响应 Cookie（长度异常 / 含连续 URL 编码二进制串） |
| 最易被忽略的检查项 | **PHP worker 是否重启**（改完 ini 不重启等于没改） |
| 下个时间节点 | **2026-12-31** PHP 8.2 安全支持到期，将新增大批永久暴露资产 |
| 项目长期价值 | 本次漏洞会过去，但“版本号不可信 + 运行时是盲区 + 修复无法自证”这个结构性问题不会过去 |
