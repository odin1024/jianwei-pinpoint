**核心技术判断（后续复用）**：
1. 版本号比对必然失效（回移补丁误报 / 版本造假漏报 / EOL 分支 / CLI≠Web 多版本共存），必须做补丁级核验（changelog → 二进制 marker → 源码特征 → 行为签名）。
2. 漏洞触发在 request startup，早于应用代码，应用层防护全部无效；mod_php 风险最高（已确认应用无关 RCE），FPM 为 109619 已验证。
3. 最有效单一检测指标：异常 `PHPSESSID` 响应 Cookie（正常为定长字母数字，泄露回显为 KB 级 URL 编码串）。
4. 最易漏检查项：补丁后 PHP worker 是否重启（不重启等于未生效）。
5. 在野利用起点 2026-10-17（早于披露 4 天），日志回溯必须从这天起。
6. 竞品 OpenAI `php2shell-checker` 仅版本比对，README 自承无法识别 backport —— 这是差异化切入点。
7. 红线：不内置 exploit；探针只发随机填充；默认不触发 OOM；禁止建议 RLIMIT_AS/RLIMIT_DATA。

**技术栈建议**：Python 3.12 + FastAPI + httpx + SQLAlchemy + ARQ + Vue3，端口 8848（对齐 seccheck），SQLite WAL 单机 / PG+Redis 集群，profile 裁剪同一套代码。

**待决策**：Q1 CLI 优先还是 Web 优先；Q2 是否开源社区版；Q4 与 seccheck/玄武/pentra 资产模型复用；Q6 定价。

## 追加：M1 实现完成（可运行）

**要求**：用户「开发出来我看看」。环境为 Python 3.13，无第三方库、无 Docker → 决定纯标准库实现。

**产出**（`p2s/` 包 + 靶场 + 测试，约 2600 行）：
- `p2s/models.py` Evidence/Verdict/Confidence/Finding 数据模型
- `p2s/phpversion.py` 版本解析（兼容 deb/rpm/麒麟后缀、RC），EOL 分支判定
- `p2s/verdict.py` 证据聚合/冲突消解/评分（0-100 + P0-P3）/处置生成
- `p2s/engine.py` 编排；`p2s/cli.py` scan/hunt/rules 三子命令
- `p2s/detectors/` D1 被动、D2 主动、D3 主机(local+SSH)、D4 补丁核验、D5 受控探针(双开关)、D6 失陷排查(12规则)
- `lab/mock_php.py` 6 persona 模拟靶场（8801-8806），无需 Docker/PHP
- `tests/` 32 个单测全通过；`run_demo.py` 端到端 6/6 符合期望

**修复的坑（可复用经验）**：
1. `Symfony\Component` 作为正则会报 `bad escape \C` → 规则表匹配必须 try/except re.error 并退化为子串匹配，否则单条坏规则会拖垮整层检测。
2. HEAD vs GET 比较时用错了变量（拿了上一个 404 探针的响应）→ 误报"存在代理层"。
3. hunt 规则对同一次攻击重复命中同一行 → 需按 (rule_id, file, line_no) 去重。
4. Windows 控制台需 `SetConsoleMode(-11,7)` 启 ANSI 才显示颜色。
5. UNKNOWN 若只给 P2 会被当成"低风险放过" → 代码里强制上调到 P1。

**关键设计决策（与文档的一致性调整）**：
- 文档判定矩阵原第 8 行"版本已修复+无补丁证据 → VULNERABLE"在实践中会把所有正常已打补丁站点判成漏洞。代码改为：**有反证（changelog 无 CVE / 构建日期早于补丁日 / phpinfo 版本更低）才判 VULNERABLE**；无任何物料证据时判 PATCHED 但置信度仅 MEDIUM。已同步修订 `04-检测引擎技术方案.md` 第 10.1 节（拆成 8 与 8b 两行）。

**未实现（对应 M2-M4）**：二进制特征字节扫描、WinRM、镜像/固件离线解析(D7)、Web 控制台、RBAC、PDF/Word 报告、OpenAPI 服务端。
