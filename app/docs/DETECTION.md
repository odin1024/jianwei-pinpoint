# 检测原理：五层收敛

> 本工具的目标不是"扫端口"，而是**回答一个问题：我的资产里有哪些跑 PHP 且版本不安全的设备**。
> 为了不误报、也不漏报，必须先把"什么是设备""它活着吗""它跑不跑 PHP"依次搞清楚。

```
  L0  存活与端口发现   TCP connect 探测（并发）
        │               100+ 端口，含安全设备管理端口(2000/10000/2082/4243…)
        ▼
  L1  服务协议识别     HTTP/HTTPS 指纹 · TLS 证书取证 · SSH/FTP/SMTP banner · favicon 哈希
        │               自签名证书自动降级；UA 与路径双回退阶梯
        ▼
  L2  存活判定  ⭐     必须拿到**有意义的协议响应**才算在线
        │               出口 NAT / tarpit 会让任意 IP 的某些端口"可连但零响应"
        ▼
  L3  设备类型分类     页面标题 · Server 头 · TLS 证书 · 登录路径 · Cookie
        │               （主）＋ 端口画像（兜底）＋ MAC OUI（厂商补充）
        ▼
  L4  PHP 暴露面       有无 PHP → SAPI → 版本 → 是否低于修复基线
```

---

## L2 是最容易被忽略、但最关键的一层

### 实测现象

本机所在网段 `192.168.1.0/24` 的一次实测：

```
254 个 IP 全部"可连接" 25 / 110 / 143 三个端口
逐个验证：连接成功，但 1.5 秒内收不到任何字节
```

这是出口防火墙做**全锥 NAT** 或对邮件端口做 **tarpit** 的典型表现。
如果只看 TCP 握手，**254 台"不存在的主机"会全部被判为存活**，
台账里就会出现几百条"未识别设备"。

### 正确判据

| 观察 | 判定 |
|---|---|
| HTTP 任意状态码（含 401 / 403 / 404） | ✅ 有意义 —— 服务真的在 |
| SSH / FTP / SMTP / IMAP 拿到非空 banner | ✅ 有意义 |
| TLS 握手成功并能完成 HTTP 交换 | ✅ 有意义 |
| TCP 连上但超时零数据 | ❌ 噪声（tarpit / NAT），**不算存活** |
| 一个端口都没响应 | ❌ 离线 |

**离线主机不写入台账、不在界面显示、也不计入统计。**

### 噪声端口的自动识别

跨主机统计端口出现频率：如果某个端口（或端口组合如 `25/110/143`）在**超过 30% 的可达主机**上都出现，
它就是网络级特征而不是主机特征。`core/identification.py::detect_noise_ports()` 实现了这个判断。

## L3 为什么用"标签"而不是"端口"

端口只能说明"有个 Web 服务"，**标签才能说明"这是什么设备"**。

实测对照：

| 主机 | 端口 | 只看端口的结论 | 用标签的结论 |
|---|---|---|---|
| 192.168.1.253 | 22, 443 | 网络设备 / 未识别 | **华为 Quidway 交换机**（证书 `CN=Quidway`） |
| 192.168.1.252 | 22, 80, 443 | 网络设备 / 未识别 | **华为 iBMC 带外管理**（页面标题 `iBMC Login`） |
| 192.168.1.254 | 22, 80, 443 | 网络设备 / 未识别 | **华为交换机**（`Server: sw3`） |
| 192.168.1.15 | 21, 445 | Windows 主机 | **FileZilla Server**（banner 特征） |
| 192.168.1.230 | 80 | Web 服务器 | **PHP 应用站点**（`Set-Cookie: PHPSESSID`） |
| 192.168.1.227 | 80, 443, 2000, 8080 | 网络设备 | **准入控制系统 NAC**（标题 `准入控制系统`） |

### 使用的证据源

| 证据源 | 采集方式 | 典型用途 |
|---|---|---|
| **页面 `<title>`** | HTTP 响应正文 | 最"人写"的产品标签，权重最高（×1.8） |
| **HTTP `Server` 头** | 响应头 | `Jump_server` / `sw1` / `fortigate` / `nginx` |
| **TLS 证书 CN / O / OU** | 握手后解析 | `CN=Quidway` / `O=jump` / `O=Huawei` |
| **登录路径** | 路径回退阶梯命中 | `/simple/view/login.html` = 华为交换机 |
| **`Set-Cookie`** | 响应头 | `PHPSESSID` → PHP；`JSESSIONID` → Java |
| **`WWW-Authenticate`** | 响应头 | `realm="FortiGate"` |
| **协议 banner** | 原始 TCP | SSH 版本里的发行版名、FileZilla 等 |
| **favicon 哈希** | `/favicon.ico` | 同款管理界面的强指纹 |
| **MAC OUI** | 本机 ARP 表 + OUI 表 | `8c:1c:da` → 深信服 Sangfor |
| **端口画像** | 端口集合 | 仅在没有任何标签证据时兜底 |

签名库在 `core/signatures.py`（128 条），每条声明 **字段 + 子串 → 设备类型 / 厂商 / 具体产品**。

> **重要纪律**：通用词（`server` / `company` / `localhost` / `root`）**绝不能**作为厂商判据。
> 实测中有大量设备证书就是 `CN=server,O=company`，把它当判据会全线误判。
> 签名库有专门的测试守着这条规则。

## 计分与置信度

```
得分 = Σ(命中签名的权重 × 字段系数)
      页面标题 ×1.8（最"人写"的标签）
      每产品取最高权重而非累加（避免 "ssh-2.0-openssh"+"openssh" 叠成 5.5 盖过 "ubuntu"）
      不同字段同时命中同一产品 → 互证加分 0.8/项

置信度 = 0.35 + 优势度×0.35 + 强度×0.30
次优候选得分 ≥ 最高分 × 40% 时并列展示
```

## L4 · PHP 暴露面

```
是否跑 PHP？
  ├─ 否 → exposure = not_php
  │        "未检测到 PHP 痕迹（X-Powered-By / PHPSESSID / 版本串均无），与 php2shell 无关"
  │        处置：不需要任何动作
  └─ 是 → 版本 → SAPI → 基线 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12
          ├─ 版本 < 基线 → exposed（严重）
          ├─ 版本 ≥ 基线 → patched
          └─ 版本未知   → unknown（待人工确认）
```

**PHP 的判定不只看 `X-Powered-By`**：实测中很多站点不暴露该头，
但会通过 `Set-Cookie: PHPSESSID`、正文里的 `Powered by PHP`、或 `.php` 链接暴露自己是 PHP 应用。

## 技术选型说明

| 手段 | 选择 | 原因 |
|---|---|---|
| 端口扫描 | **TCP connect**（非 SYN） | 不需要 root / 原始套接字，Windows / 容器 / 客户环境都能跑；代价是慢一些且会留完整连接日志 |
| TLS | 不校验证书 | 内网设备几乎都用自签名证书，校验必然失败 |
| 证书解析 | `cryptography` 库 | 需要解析自签名证书的 CN/O/OU，标准库做不到 |
| SNMP | **不使用** | 实测该网段 161 端口被防火墙拦截，收益为零 |
| 反向 DNS | 尝试但不强依赖 | 实测该网段无 PTR 记录 |
| OUI 在线库 | 使用内置精简表 | IEEE 在线接口对本工具返回 418（反爬） |
| favicon | sha256（可选） | 同款管理界面的强指纹 |

## 性能

| 模式 | 每台耗时 | /24 预计 | 内容 |
|---|---|---|---|
| 快速 | ~1.6s | ~7 分钟 | 20 个常见端口 + SSH/banner + HTTP 快速探测 |
| 深度 | ~2.5s | ~11 分钟 | 110+ 端口 + HTTP 指纹 + TLS 证书 + 路径/UA 阶梯 + favicon |

单台内部**各端口并行探测**（12 线程），而不是串行 —— 一台开 8 个端口的设备，
串行要 8 倍时间，并行几乎不增加耗时。
